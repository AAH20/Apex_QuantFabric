# Portfolio contract seams

Projects keep their names, licenses, workloads and evidence. This repository implements no source-level portfolio integration yet. Dotted architecture edges are candidates requiring rights and conformance review.

| Group | Candidate interface | Necessary gate |
|---|---|---|
| Quant Whale / microstructure | Point-in-time workload and model/policy fixture | Authorized data, schema, temporal/numerical meaning |
| GraphRAG / graph optimization | Offline dependency selection and candidate plan | Instance-specific quality, scope and proposal-only authority |
| Compiler / ContractForge | Candidate implementation and bounded semantic contract | New profile legality and independent qualification |
| Tick | Separately bounded streaming implementation | New RTL profile, shell and physical qualification |
| ULL | Host transport/process or file interchange | AGPL rights analysis, framing and native measurement |
| PerfAtlas | Evidence import and comparison | Compatible metric populations, source identity and scope |
| GRC Claw / identity | Reviewed release authorization and evidence receipts | Explicit authority/system-of-record contract |
| Multi-cloud control loop | Environment inventory and reviewed deployment change | Actual inventory and mutation permissions |
| Network change twin | Dependency/path-change scenario | Topology identity, physical facilities and path evidence |
| Revenue Twin / FinOps | Measured cost/capacity scenario | Declared invoices/allocation, no inferred cash savings |
| Swarm/evaluation | Offline analysis and candidate generation | No event-path action authority |

The portfolio's ten flagship identities and three maintenance priorities remain distinct. See [Ahmed Hassan's profile](https://github.com/AAH20/AAH20). The initial product buyer remains a quant infrastructure owner making one release decision.
